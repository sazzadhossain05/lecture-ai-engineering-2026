According to Lecture 3 (p. 43), the three ways to stop an agent loop are:

1. **Model**: Ends when it stops calling tools or when its output ends. (However, relying on the model alone can cause it to stop too early or never stop.)
2. **Harness**: Stops the loop at a set limit (such as repeated failures, or when a time or budget limit is exceeded), which is counted by the harness rather than self-reported by the model (Lecture 3, p. 43).
3. **Human / monitor**: Stops the process from the outside (such as a person pressing a stop button), because the agent cannot turn itself off (Lecture 3, p. 43).

Regarding who should decide whether the task is done, Lecture 3 (p. 44) points out that **someone other than the working model** should decide if it's "done." This can be handled by:
- Having another separate model judge the endpoint (e.g., a separate small model evaluating whether the goal has been met, is still in progress, or is impossible) (Lecture 3, p. 44).
- Using an evaluation script or test suite that is fixed and that the agent cannot modify (Lecture 3, p. 44).
