### Why RAG is recommended before Fine-Tuning (FT) for adding knowledge
* **Fine-tuning does not fix the knowledge problem:** Fine-tuning is typically used to change output formats (such as enforcing a specific JSON structure), style, tone, or behavior rather than reliably instilling factual knowledge (Lecture 2, p. 53). 
* **Fact-dependent questions require external materials:** Questions that depend on specific facts (such as details found only in lecture materials) are unlikely to be answerable via fine-tuning alone. Instead, the course recommends using RAG to retrieve and provide those materials directly to the model (Lecture 2, p. 53).

### How the example chatbot in Lecture 01 uses RAG
The example chatbot follows a **"search, then answer"** approach via Retrieval-Augmented Generation (Lecture 1, p. 49):
1. **Preparation (Indexing):** It collects source materials (like lecture documents), filters out unneeded content, splits the documents into small pieces (chunking), and builds a search index (Lecture 1, p. 49).
2. **Answering:** When a user asks a question, a retriever finds relevant materials from the index. The LLM then generates an answer based on those retrieved materials and displays the source materials alongside the response (Lecture 1, p. 19, 49).

***

*Hint for further thinking:* Consider how separating knowledge retrieval from the language model's parametric memory makes it easier to update your chatbot when the underlying source documents change.
